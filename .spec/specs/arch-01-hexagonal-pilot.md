## Objective
Move the backend from the layered structure (`controllers/ services/ entity/ repository/ config/ exeptions/ utils/`) to the **"Hexagonal Pragmática"** model (layout v2, D-50) — package-by-feature `<feature>.{api, application(port, usecase), domain, infrastructure}`, framework-free domain, **one `<Verb><Noun>UseCase` class per operation**, output ports in `application.port` — **without changing any behaviour**. This spec proves the process, the checker and the ArchUnit gate on the **smallest feature (`account`)** before the money flows are touched (ARCH-02).

## Constraints (D-41: behaviour is frozen)
Same HTTP statuses, JSON bodies and messages · same OpenAPI contract (no change to `src/main/resources/swagger/*.yaml`) · same Flyway schema (no new migration) and Hibernate `validate` passing · same Kafka topic and payload bytes · same test count or higher, no test deleted to get green · packages move with `git mv`, a commit never mixes a move with a behaviour change · base package `com.dowglasmaia.financialtransaction` unchanged.

## Scope
1. **Inventory + class mapping table for the whole backend** (skill `migrate` step 1) and the owner's approval. The agent verifies the proposal below against the code, measures each service's lines/collaborators (decision D4) and presents the final table.
2. **Foundation:** `archunit-junit5` (test) + `ArchitectureTest` generated by the skill's scaffold script with `LEGACY_PACKAGES = {controllers, services, entity, repository, config, exeptions, utils}` (only those not yet migrated); `scripts/check-architecture.mjs --legacy …` documented in `como-executar`/README; `shared` kit: `GlobalExceptionHandler` (moved from `config.HandlerException`, same statuses/bodies/messages), `shared.error` base classes, `Clock` bean if missing.
3. **Migrate the `account` feature:** `Account`, `Agency`, `User` (the account holder), their repositories, `AddAmountService`, `FindAccountByNumberAndUserIdService`, `AgencyService` and the caller resolution (`CurrentUser`), plus the demo seed.
4. **Security split (needs approval):** `SecurityConfig` stays generic in `shared.security` and receives the "customer linked to a user" rule as an `AuthorizationManager` **bean provided by the `account` feature** (`account.infrastructure.security.CustomerLinkedAuthorization`, backed by `CheckCallerLinkedUseCase`); `CurrentUser` becomes a port `CallerIdentity` (`account.application.port`) + `account.infrastructure.security.JwtCallerIdentityAdapter`, consumed by `GetCurrentAccountUseCase`. `shared` imports no feature (A10).

**Out of scope:** the `transaction` feature (ARCH-02), any behaviour/contract/schema change, removing dead code (BE-08), renaming the `exeptions` typo classes (decided in the mapping, done in ARCH-02).

> **Layout v2 (owner decision, 2026-11-03, after the first push; D-50):** the skill was changed to `api / application(port, usecase) / domain / infrastructure` with **one `<Verb><Noun>UseCase` class per operation**, and the account migration was redone to it on the same branch. The mapping below and the evidence lines show the final layout. The first implementation (one `AccountService`, ports in `domain`, `infra.*`) is in the branch history (up to commit `d277217`).

## Result
**Implemented 2026-11-03** on `spec/arch-01-hexagonal-pilot` (pushed, no PR). The foundation (ArchUnit gate, handler in `shared.web`, security in `shared.security`) and the whole `account` feature (domain, persistence adapters, the account use cases, caller identity, customer-linked authorization, `AccountController`, demo seed) now follow the model. 18 classes and interfaces of the old layout were moved (11) or removed (7); legacy files went from 49 to 32.

**Executed:** `mvn clean verify` (156 tests, BUILD SUCCESS), the standalone checker (0 violations), `git diff main -- resources` (empty), the API rebuilt in Docker (health UP, 401 without token), Playwright e2e (21 passed) against that API, red-then-green runs of the new tests.
**Only written / not run:** `api-ci` on the PR; the standalone checker is not a CI step yet (only `ArchitectureTest` runs in `mvn verify`); coverage percentage not recorded this time.

**Layout v2 (D-50):** after the first push the owner chose the scaffold-style layout; the skill, its example (46 tests) and the account code were redone to `api / application(port, usecase) / domain / infrastructure` with one use case per operation, on this same branch (commits from 1f34738 on).

**Accepted limitations / deviations (all approved or listed above):**
- `./mvnw` is broken on this machine (`distributionUrl` is rejected) and JDK 21 needs `MAVEN_OPTS="-Djavax.net.ssl.trustStoreType=WINDOWS-ROOT"` plus `~/.docker-java.properties` (`api.version=1.44`) for Testcontainers; none of this is in the repository.
- Lombok 1.18.42 is the first commit (build only).
- The three `exeptions.*` classes were not moved (ARCH-02); `ObjectNotFoundExeption` and `UnprocessableEntityExeption` got one-argument constructors so `application` does not import `HttpStatus`. Their `httpStatus` field is never read by the handler (it answers fixed statuses), so the `302 FOUND` that `debit` used to pass is gone without any visible effect.
- The scaffold's generic `shared` kit was not generated; the skill's checker and ArchUnit template were fixed so a legacy package is not treated as a feature (skill commits 0303795 and 0e5c726, local and not pushed).
- Dead code left for BE-08: `AccountJpaRepository.findByNumberAndUser`.

**Open mapping decisions for ARCH-02:** split of the transaction services by D4 (Pix 148 lines with its own `MaiaBankClient`; deposit, withdrawal, recharge and statement total about 313 lines, so at least two services); exception names and the `shared.error` base classes (status mapping must stay identical); `Transaction`/`OutboxEvent` become plain-id relations; `config.kafka` goes behind a `RechargeEventPublisher` port; `ValidateBodyRequest` and the validators under `utils` (business rule vs shape check).
