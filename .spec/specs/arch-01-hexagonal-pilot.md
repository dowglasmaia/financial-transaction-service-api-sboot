## Objective
Move the backend from the layered structure (`controllers/ services/ entity/ repository/ config/ exeptions/ utils/`) to the **"Hexagonal Pragmática"** model — package-by-feature, framework-free domain, one service per feature, ports only for outputs, JPA/web/clients as infra — **without changing any behaviour**. This spec proves the process, the checker and the ArchUnit gate on the **smallest feature (`account`)** before the money flows are touched (ARCH-02).

## Constraints (D-41: behaviour is frozen)
Same HTTP statuses, JSON bodies and messages · same OpenAPI contract (no change to `src/main/resources/swagger/*.yaml`) · same Flyway schema (no new migration) and Hibernate `validate` passing · same Kafka topic and payload bytes · same test count or higher, no test deleted to get green · packages move with `git mv`, a commit never mixes a move with a behaviour change · base package `com.dowglasmaia.financialtransaction` unchanged.

## Scope
1. **Inventory + class mapping table for the whole backend** (skill `migrate` step 1) and the owner's approval. The agent verifies the proposal below against the code, measures each service's lines/collaborators (decision D4) and presents the final table.
2. **Foundation:** `archunit-junit5` (test) + `ArchitectureTest` generated by the skill's scaffold script with `LEGACY_PACKAGES = {controllers, services, entity, repository, config, exeptions, utils}` (only those not yet migrated); `scripts/check-architecture.mjs --legacy …` documented in `como-executar`/README; `shared` kit: `GlobalExceptionHandler` (moved from `config.HandlerException`, same statuses/bodies/messages), `shared.error` base classes, `Clock` bean if missing.
3. **Migrate the `account` feature:** `Account`, `Agency`, `User` (the account holder), their repositories, `AddAmountService`, `FindAccountByNumberAndUserIdService`, `AgencyService` and the caller resolution (`CurrentUser`), plus the demo seed.
4. **Security split (needs approval):** `SecurityConfig` stays generic in `shared.security` and receives the "customer linked to a user" rule as an `AuthorizationManager` **bean provided by the `account` feature**; `CurrentUser` becomes a port `CallerIdentity` (`account.domain`) + `account.infra.security.JwtCallerIdentityAdapter`, consumed by `account.application.AccountService`. `shared` imports no feature (A10).

**Out of scope:** the `transaction` feature (ARCH-02), any behaviour/contract/schema change, removing dead code (BE-08), renaming the `exeptions` typo classes (decided in the mapping, done in ARCH-02).

## Proposed mapping — whole backend (confirm in task 1)
| Today | Target | Notes |
|---|---|---|
| `entity.Account`, `entity.Agency`, `entity.User` | `account.domain.{Account, Agency, User}` (pure) + `account.infra.persistence.{AccountEntity, AgencyEntity, UserEntity}` | keep `@Table` names (`account`, `agency`, `usuario`); `User` keeps its name (rename only if the owner asks) |
| `repository.{Account,Agency,User}Repository` | `account.infra.persistence.*JpaRepository` + ports `account.domain.{AccountRepository, AgencyRepository, UserRepository}` + `*RepositoryAdapter` | the atomic conditional `UPDATE … WHERE balance >= :amount` stays an atomic query behind the port method `tryDebit` (never a read-modify-write) |
| `services.client.account.AddAmountService(+Impl)` | `account.application.AccountService` (`debit`, `credit`) | delete the interface and the `*Impl`; transaction features call `AccountService` (D6) |
| `services.client.account.FindAccountByNumberAndUserIdService(+Impl)`, `services.client.agency.AgencyService(+Impl)` | methods of `account.application.AccountService` | one service for the feature |
| `services.client.CurrentUser` | port `account.domain.CallerIdentity` + `account.infra.security.JwtCallerIdentityAdapter`; `AccountService.currentAccount()/isLinked()` | `ForbiddenExeption` for an unlinked caller keeps its message and 403 |
| `config.security.SecurityConfig` | `shared.security.SecurityConfig` + `account.infra.security.CustomerLinkedAuthorization` (bean) | same filter chain, same JWT validation, same JSON 401/403 |
| `config.HandlerException` | `shared.web.GlobalExceptionHandler` | statuses, bodies, messages identical |
| `config.db_massa_test.{DBService, TestConfigDb}` | `account.infra.seed.DemoDataSeeder` (`@Profile("local")`/test as today) | seed needs account classes, so it cannot live in `shared` (D8) |
| `exeptions.*` | `shared.error.*` (names decided in task 1; renames in their own commit) | messages unchanged |
| *(ARCH-02)* `controllers.*`, `services.*`, `entity.Transaction/Outbox*/enums`, `repository.Transaction/Outbox*`, `config.kafka.*`, `services.client.maiaBank.*`, `utils.*`, `services.model.*`, `services.impl.mapper.*` | `transaction.*` and `shared.*` | see `arch-02-hexagonal-transaction.md` |
